--> we can organize playbooks into a directory structure called roles
--> adding more and more functionality to be playbook will make it difficultto maintain a single file


default -> it stores the data about role / applications
define variable

example :  if you want to run to port 80 or 8080 then variable need to define in the path

files - > it contain files need to be transfered to the remote VM (static files)

handlers - > they are trigger or task we can segregate all the handlers required in playbook

meta -> this directory contain file that establish roles dependencies

example : Author name, supported platform , dependencies if any

Tasks - > it contain all the tasks that is normallly in the playbook 
examples : installing pakages and copies files


vars - >  variable for the role can be specified in the directory and used in your cnfiguration file both vars and default store variable
